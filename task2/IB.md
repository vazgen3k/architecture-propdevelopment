## Проверочный лист безопасности для бизнес-систем PropDevelopment

### Обоснование выбора разделов

Для проверки бизнес-систем PropDevelopment в проверочный лист включены разделы:
1. **Управление доступом**
2. **Безопасность данных**
3. **Защита инфраструктуры**
4. **Управление инцидентами**
5. **Специфические аспекты (ограниченно)**

Такой набор выбран, потому что основные риски компании связаны не с физической безопасностью как таковой, а с:
- неконтролируемыми потоками данных между системами;
- несколькими точками регистрации клиентов;
- недостаточным разграничением доступа;
- небезопасными партнёрскими API;
- риском утечки персональных данных;
- необходимостью подтвердить готовность к аудиту безопасности и соответствие требованиям законодательства.

### Системы, попадающие в проверку

В рамках проверочного листа рассматриваются следующие бизнес-системы:
- витрина продаж;
- `client-mart-app`;
- `client-crm-app`;
- витрина сервисов для собственников;
- `tenant-core-app`;
- CRM собственников;
- `accountant-service-1`;
- хранилище данных;
- внешние интеграции с управляющими компаниями;
- интеграции с госорганами;
- базы данных перечисленных систем.

## Краткий вывод

По данным кейса у PropDevelopment уже можно уверенно подтвердить:
- наличие аутентификации пользователей;
- использование firewall для внешнего доступа;
- регулярное резервное копирование баз данных.

Одновременно уже видны критичные пробелы:
- отсутствует системный контроль потоков данных;
- не реализовано корректное разграничение доступа;
- нет признаков зрелого Data Governance;
- аудит безопасности только планируется;
- работа партнёрских API несёт прямой риск нарушения изоляции данных.

Это означает, что наибольший фокус проверки должен быть на:
1. правах доступа и изоляции данных;
2. управлении персональными данными;
3. безопасности интеграций;
4. готовности к инцидентам и аудиту.
